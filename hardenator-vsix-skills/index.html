Option 01 · Inspection stationTECHNICAL DETAILS · 1 / 3

Start at the analyst’s desk.

A desktop inspection station for VSIX extensions and AI skills. Review a file before deciding whether it should enter the internal network.

DEPLOYMENT

One workstation

Local UI, bounded scan workers and a local evidence store. No shared server required.

  • VS Code/Cursor VSIX packages
  • SKILL.md and complete skill bundles
  • Preserve original files and SHA-256
ANALYSIS

Inspect beyond CVEs

Review code, instructions and their relationship to the advertised task.

  • Dedicated VSIX analysis, proposed
  • SkillSpector skill analysis
  • IQ evidence import or connector*
DECISION

An evidence-backed review

Findings, confidence and inspection gaps, not a blanket “safe” score.

  • Allow / review / block / incomplete
  • Analyst disposition and export
  • Optional approved local model
Inspection ≠ enforcement.The analyst’s report does not stop a separate file transfer. *IQ version, licensing and interface must be confirmed. Visual Studio VSIX is a separate scope decision.

Option 02 · Central review portalTECHNICAL DETAILS · 1 / 3

One server. One review process.

The recommended pilot: employees submit through a browser, security teams review from a shared queue, and every decision has an audit trail.

CLIENTS & IDENTITY

A browser for everyone

No desktop installation. Responsive views for submitters, reviewers and administrators.

  • Enterprise sign-in and role controls
  • Submitter cannot self-approve
  • Team-scoped artifacts and history
ON-PREMISES SERVER

Shared, not mixed

API, job queue, database and quarantined file storage in one managed deployment.

  • Separate isolated scan workers
  • Time, size and resource budgets
  • No user secrets in scan jobs
POLICY & PRIVACY

Review with context

Correlate skill, VSIX and IQ evidence against the exact submitted bytes.

  • Required checks gate approval
  • Retention and audit controls
  • Cloud models opt-in, local alternative
The portal records approval.It is not yet a network barrier. Files entering by email, USB or another route are outside its control unless that route is integrated or restricted.

Reuse SkillSpector as a worker. Add VSIX-specific analysis and the enterprise service. Wazatator can add optional quality/behavior evidence, never the security verdict.

Option 03 · Enforced admission gatewayTECHNICAL DETAILS · 1 / 3

Make approval a condition of entry.

Connect the portal to the customer’s actual file-transfer boundary. No approved decision, no release through the governed path.

INTAKE BOUNDARY

Quarantine first

Untrusted artifacts land in a dedicated intake zone, before the trusted destination.

  • Authenticated transfer API
  • Archive validation and safe extraction
  • Immutable original and digest
EVIDENCE & POLICY

Combine, don’t replace

Keep IQ dependency/license evidence and skill/VSIX behavior findings distinct.

  • Required scanner completion
  • Versioned admission policy
  • Review queue for ambiguous cases
RELEASE AUTHORITY

Exact bytes, exact permit

A separate release component validates approval and rechecks the digest before transfer.

  • Hash, policy and expiry binding
  • Worker has no release credentials
  • Failures and mismatches stay held
A gateway only controls its path.The customer must route relevant transfers through it and restrict bypasses. A file changed after approval requires a new decision.

Deployment can start as one on-premises installation with separate trust zones/processes. Higher availability and worker scaling are sizing decisions, not assumed pilot features.

Option 04 · Controlled internal catalogTECHNICAL DETAILS · 1 / 3

Approval is a lifecycle, not a moment.

Extend admission into controlled distribution: users discover approved versions, while updates and revocations remain under policy.

CURATED DISTRIBUTION

A trusted internal source

Catalog the approved bytes, business owner, supported host and decision evidence.

  • VSIX and skill bundle records
  • Role-based access to artifacts
  • Version and digest pinned together
CHANGE CONTROL

Review every update

A trusted publisher or previously approved version is not a permanent allow.

  • New version → new intake decision
  • Rescan after policy/intelligence changes
  • Revoke distribution when warranted
SUPPORTED ENDPOINTS

Close the bypass routes

Use supported IDE/agent controls to restrict installation and automatic updates.

  • Host-specific integration required
  • Installed-copy inventory if connected
  • Revocation/remediation acknowledgement
A catalog is not universal endpoint control.Catalog revocation blocks future governed downloads. Removing an installed copy requires a supported endpoint integration and an explicit response policy.

Suggested sequence: prove the portal workflow, integrate the transfer gateway, then add catalog and endpoint controls for selected hosts. Optional Wazatator evaluation remains separate quality evidence.
