02 THE REQUIREMENT

Three constraints that define a sovereign AI programme

ESL · FACTORY

Data Sovereignty

Source never leaves

Every character of your repository, every prompt, every tool call, every log line is a potential disclosure vector. The only safe answer is: nothing goes out.

Model Sovereignty

Weights live on your silicon

A model you cannot inspect, pin, or re-run offline is not a sovereign asset. You must be able to freeze a known-good version and run it indefinitely with zero vendor dependency.

Operational Sovereignty

No external control plane

A SaaS orchestrator that holds routing rules, approvals, or audit logs is a single point of foreign control. The agent, its policies, and its history must sit inside your network.

03 THE GAP

Why standard coding copilots cannot be used

ESL · FACTORY

Cloud copilots

Every prompt, every file, every snippet of your code is sent to a third-party API. There is no architectural option to disable this — it is the product.

"Enterprise" tiers

A no-training promise is not an air-gap. Traffic still crosses borders. Vendor outages still break your pipeline. Jurisdiction still applies to the host.

Local model, hosted agent

Running a local model with a cloud-hosted agent harness is the worst of both worlds — the orchestrator phones home, and you cannot audit what it says.

What is actually required

  • Agent orchestrator inside the perimeter
  • Model weights on local GPUs
  • All configuration via local files
  • Telemetry to your own collector, or off
  • Verifiable: no path reaches the internet
  • Reproducible: same build, same result, offline, next year

This is the exact shape of Factory's air-gapped deployment.

07 INSTALLATION

Four steps to a working private deployment

ESL · FACTORY

Step 01 · Hardware

Rack the GPU server

4× H100 80 GB (SXM or PCIe) in a single node. NVLink helps tensor-parallel inference. Linux host, CUDA 12.4+, Docker or bare-metal Python 3.11.

Step 02 · Weights

Mirror the models

Download open-weight models on an internet-connected box. Verify checksums. Carry via approved media. Land under /models on the GPU host.

Step 03 · Inference

Serve the model

Launch vLLM (production) or LM Studio (dev) as an OpenAI-compatible endpoint on :8000/v1 or :1234/v1.

Step 04 · Droid

Point Droid at it

Install Droid CLI on workstations. Set customModels[].baseUrl in ~/.factory/settings.json. Airgap mode refuses to start without a custom model.

08 CONFIGURATION

One file. Three lines that matter.

ESL · FACTORY

~/.factory/settings.json

The Droid CLI reads a single JSON file. The three lines that matter are the base URL, the model id, and (optionally) a key. Everything else is defaults.

Three endpoints you will use

  • http://localhost:1234/v1 — LM Studio
  • http://localhost:8000/v1 — vLLM
  • http://localhost:11434/v1 — Ollama

All three speak the OpenAI Chat Completions protocol. Droid treats them identically.

// ~/.factory/settings.json
{
  "customModels": [
    {
      "model":        "qwen3-235b-a22b",
      "displayName":  "Qwen 3 · 235B · internal",
      "baseUrl":      "http://gpu-01.lan:8000/v1",
      "apiKey":       "${INTERNAL_VLLM_KEY}",
      "provider":     "generic-chat-completion-api",
      "maxOutputTokens": 16384
    },
    {
      "model":        "llama-3.1-405b-q4",
      "displayName":  "Llama 3.1 · 405B · Q4",
      "baseUrl":      "http://gpu-02.lan:8000/v1",
      "provider":     "generic-chat-completion-api"
    }
  ],
  "telemetry": {
    "endpoint": "http://otel.lan:4318",
    "external": false
  }
}

Models appear in the Droid /model selector. The CLI refuses a turn without at least one custom model — Factory's reliability contract for air-gap mode.

09 OPTION A · LM STUDIO

The operator-friendly local inference server

ESL · FACTORY

When LM Studio is the right choice

  • Evaluation phase — stand up models in minutes with a GUI
  • Small teams, moderate concurrency (1–5 users)
  • Operators who don't want to script CUDA, Python, or GPU scheduling
  • Rapid model swap during a proof-of-value
  • Desktop-grade dev environment next to the GPU
OpenAI-compatible by default
Point your SDK calls at localhost:1234 instead of api.openai.com. Your application runs against a model that never leaves your machine.

Limits to know

  • GUI-first — not ideal for headless rack-mounted servers
  • Lower throughput than vLLM at high concurrency
  • Less flexible on tensor-parallel schemes
  • Licensing — check with your legal office

Recommendation

Use LM Studio for the proof-of-value phase. The GUI lets security and operations staff see what is running, confirm model identity, and watch requests in real time.

10 OPTION B · vLLM

The production inference engine

ESL · FACTORY

Why vLLM for the real deployment

  • PagedAttention — 2–4× higher throughput than naive servers
  • Continuous batching — many developers in parallel
  • Tensor-parallel across 2 / 4 / 8 GPUs with one flag
  • INT4 / INT8 / FP8 quantisation out of the box
  • Apache 2.0 licence — no commercial-use ambiguity
  • Serves entirely from local disk — the canonical air-gap backend

Operational posture

Run as a systemd service on the GPU host. Expose over the internal LAN only. Point every developer workstation at the same cluster through baseUrl. Scale by adding GPU nodes behind a reverse proxy.

# Launch Qwen 3 235B on 4× H100 80GB
# INT4 fits in ~140 GB; TP=4 splits across cards

vllm serve /models/qwen3-235b-a22b-int4 \
  --tensor-parallel-size 4 \
  --gpu-memory-utilization 0.90 \
  --max-model-len 32768 \
  --quantization awq \
  --host 0.0.0.0 \
  --port 8000 \
  --api-key ${INTERNAL_VLLM_KEY}

# Verify from a workstation
curl http://gpu-01.lan:8000/v1/models \
  -H "Authorization: Bearer $KEY"

Single command. Hundreds of requests per minute. Deterministic, repeatable, scriptable. The reference backend for an air-gapped Factory Droid cluster in production.

Why this specific configuration

  • 320 GB aggregate VRAM is the floor for frontier MoE at usable precision
  • H100 over A100 — FP8 and 2× bandwidth matter for first-token latency
  • Single node keeps tensor-parallel over NVLink; avoids slow inter-node fabric
  • 4×, not 8× — sweet spot for cost per developer; 8× is 2× money for <2× throughput at this scale

Capacity planning

One 4×H100 node comfortably serves 15–30 concurrent developer sessions on a 100–235B model with vLLM continuous batching. Add a second node when p95 time-to-first-token exceeds 2 seconds.

Definition

An agent harness is the full software system around the LLM: the prompt scaffold, the tools, the context strategy, the verification loop, the policy layer, and the memory. The LLM is one component — the harness is the product.

The frame
If you're not the model, you're the harness.
— widely cited across 2026 harness literature

Why this matters for government deployment

You will not run the largest frontier model. You will run a pinned, audited, open-weight model. The harness is what turns that model into a competent engineer.

17 HOW DROID COMPENSATES

What the Droid harness does for the model you host

ESL · FACTORY

Context Engineering

Just-in-time retrieval, aggressive compaction

The LLM only ever sees the slice of the repo it needs for the current step — never the whole codebase. This lets a 32K-context local model behave like a 1M-context frontier one.

Disciplined Tool Surface

Fewer than ten tools, each one strong

Read, write, grep, run tests, inspect diff, open PR. Each tool minimises ambiguous outputs, so even a smaller model routes correctly.

Deterministic Verification

Every output passes a non-LLM check

Syntax parse, type check, test run, lint — a deterministic gate before anything reaches the human. Catches hallucinations smaller models produce more often.

Planner / Executor split

Think once, execute many

A plan is formed up front, then executed with cheap tool calls. The expensive reasoning step is spent where it matters most — not re-done on every subtask.

Policy & Approvals

You decide where humans gate

Which actions auto-run, which require review, which are forbidden — enforced by the harness, not the model. Compliance is a configuration file.

Observability

Every token logged locally

OpenTelemetry traces land on your collector. You can replay any agent run, inspect any decision, prove any claim about what the system did.

19 VERIFICATION & AUDIT

How to prove the air-gap holds

ESL · FACTORY

Network-level proofs

  • Default-deny egress firewall at the perimeter
  • Host firewall blocks :443 to unknown IPs
  • DNS points only at internal resolvers
  • Packet capture during a Droid session shows zero outbound
  • No TLS SNI for *.factory.ai or vendor domains

Application-level proofs

  • Droid startup refuses without customModels
  • No sign-in, no OAuth, no external IdP token exchange
  • Telemetry endpoint is explicit, points at your collector

Audit trail

  • Every prompt sent to the LLM — captured
  • Every tool call issued — captured
  • Every file read, every file written — captured
  • Every test executed and its outcome — captured
  • Approval decisions by name and timestamp — captured

All of this flows to your OpenTelemetry collector at a URL you control. Not Factory's. Not a third party's. Yours.

The posture
Air-gap is a reliability contract Factory honours in software. The enforcement comes from your firewall. Both halves are needed. Both are present.
