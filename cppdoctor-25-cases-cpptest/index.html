The 13 bug-line findings come from 11 distinct rules. The violet structural rules dominate the noise floor: in 25 single-file demo programs they fire on every translation unit by design.

Why the 12 invisible bugs stay invisible

Dynamic behavior (9)1, 2, 3, 4, 5, 9, 10, 17, 25: refcount cycles, thread join in destructor, callback re-entry, thread argument copies, static destruction order, aliasing. Flow analysis is path/value based; it has no model of std::function dispatch, std::thread copies or jthread joins.
Temporary semantics (3)7, 8, 14: truncation hidden in std headers, ofstream recreation ordering, ternary common-type temporaries. String invalidation is modeled (case 11 was caught); these siblings are not.
Contracts (2)21 strict weak ordering and 23 real-time no-locking live outside the type system: they need libc++ hardening and RealtimeSanitizer.
What C++test cannot replaceSanitizers catch 1, 2, 3, 4, 5, 14, 25; Clang warnings catch 13, 24 (also caught here); clang-tidy catches 19 (also caught here); GCC -Wconversion catches 7. Cases 6, 17, 18, 20 are the book's true "understand the language" territory.
Recommended Rules found 2/25. Flow Analysis alone 5/25. MISRA C++ 2023 + Flow Analysis Aggressive: 9/25 purposeful (6 detected + 3 flagged) plus 3 incidental style hits. The delta over flow analysis alone comes almost entirely from MISRA semantic rules: 4_6_1-b (19), 7_0_2-a (24), 8_0_1-b (13), 15_1_1-a (15), 9_5_2-a (16), 7_0_3-a (20).
