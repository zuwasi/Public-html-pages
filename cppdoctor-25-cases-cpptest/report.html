Headline

Across four configurations the best result is the custom merged MISRA C++ 2023 + Flow Analysis Aggressive config: 9 of 25 bugs get a purposeful finding (6 detected outright, 3 flagged on the right line for the right hazard family), plus 3 incidental style hits on bug lines. 12 of 25 cases produce no finding anywhere near the bug. Recommended Rules alone finds 2 of 25; Flow Analysis alone 5.

Why the 12 invisible bugs stay invisible

  1. Dynamic behavior absent (cases 1, 2, 3, 4, 5, 9, 10, 17, 25): refcount cycles, thread joins, callback re-entry, thread argument copies, static destruction order, aliasing. Flow analysis is path/value based and has no model of std::function dispatch, std::thread copies, or jthread join-in-destructor.
  2. Temporary semantics (7, 8, 14): truncation hidden in std headers, ofstream recreation ordering, ternary common-type temporaries. String invalidation is modeled (case 11); these siblings are not.
  3. Contracts outside the type system (21, 23): strict weak ordering and real-time no-locking need libc++ hardening and RealtimeSanitizer.

Method and reproduction

Repository: C:\Projects\CPPdoctor\cppdoctor-25-cases (25 case files verbatim from the book, the book's fixes, ground-truth bug lines in cases.json, merged config in MISRA-CPP-2023-FA-Aggressive.properties). Scans: ./run_cpptest.sh (builtin Recommended Rules / Flow Analysis Standard / Flow Analysis Aggressive + the custom merged config), GCC 13.3 import (bdf.import.compiler.family=gcc_13-64), reports parsed from report.xml with parse_findings.py. A finding counts as a hit only if its line equals a ground-truth bug line for that case; tiers: detected (finding expresses the bug), flagged (right line and hazard family), incidental (style rule coincidentally on the line).
