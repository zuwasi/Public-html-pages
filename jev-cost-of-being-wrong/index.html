03 / Before the math earns your trust

Jev makes
judgment cheaper.
It does not make
mistakes cheaper.

Decision theory, applied to AI. A low API bill says nothing about the cost of a wrong action.

  • 01
    Validate probabilities on your workload.
    Check observed outcomes against predictions, including important subgroups and changing inputs.
  • 02
    Price the whole mistake.
    Include recovery, delay, customer harm and reviewer error, not only the face value of a transaction.
  • 03
    Keep hard policy outside the model.
    Authorization, legal requirements and mandatory reviews cannot be bought away by a favorable expected value.
This simplified comparison assumes negligible review error. In practice compare automatic-action loss with review cost plus residual expected loss after review.

04 / Code controls

Turn probability
into policy.

One small function. No agent framework. No payment execution. Just an explicit, testable routing recommendation.

PYTHON / NO DEPENDENCIESILLUSTRATIVE POLICY

Inputs: a validated probability and finite, nonnegative cost estimates. A policy veto or invalid probability routes to review. Equal expected costs also route to review.

“Automation candidate” is not authorization. Existing access controls and execution safeguards still apply.
decision_policy.py
def route(p_correct, loss_if_wrong, review_cost, *, policy_ok):
    if not policy_ok or not 0 <= p_correct <= 1:
        return "REVIEW"

    expected_loss = (1 - p_correct) * loss_if_wrong
    return (
        "AUTO_CANDIDATE"
        if expected_loss < review_cost
        else "REVIEW"
    )

print(route(0.99, 20, 5, policy_ok=True))
print(route(0.99, 20_000, 5, policy_ok=True))

# Equal costs? Review. Policy veto? Review.
assert route(0.75, 20, 5, policy_ok=True) == "REVIEW"
assert route(1.0, 20, 5, policy_ok=False) == "REVIEW"

$20,000 case → REVIEW

05 / The subtle Jev trap

confidence
is not P(correct).

TypeSafe describes confidence as a statistic derived from the shape of the answer's probability distribution. Do not use it interchangeably with the probability of the selected outcome.

Type-safe.Not necessarily truth-safe.

A perfectly valid enum can still select the wrong action.

Inside an existing Jev Choice response
answer = response.answers["department"]

# Probability of the selected classification:
p_selected = answer.probabilities[answer.choice]

# Not an interchangeable substitute:
# p_selected = answer.confidence
  • !
    A classification is not an entire action.
    The probability of “billing” is not the probability that issuing a refund is safe.
  • !
    Calibration still needs evidence.
    Validate against labeled workflow examples before assigning economic meaning to the number.
