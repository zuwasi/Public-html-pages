How a coding agent plans, calls tools, and manages context — its harness — matters more than the raw LLM inside it. Across three independent experiments, Amp beats Claude Code running Claude Fable 5 at max effort: faster, cheaper, and just as correct — from NP-hard quantum compilation to a deliberately silly browser game.

The claim

Same model. Different agent. Very different results.

A frontier model is the engine; the agent harness is the rest of the car — the transmission, steering, and driver. Give two agents the identical model and the identical task, and the better harness wins on wall-clock time and dollars while matching quality. Industry write-ups such as the Kaggle “The New SDLC with Vibe Coding” whitepaper argue the harness/workflow carries the overwhelming share of real-world outcome — a claim these experiments turn out to be consistent with.

The three experiments below stress the same thesis from three angles: a hard/technical domain, a formal-correctness challenge, and an accessible/fun domain anyone can judge.

Experiment 01 · the hard domain

Quantum-compilation optimization

The benchmark asks agents to implement, from zero, the search cores of a fault-tolerant quantum compiler — problems that are genuinely NP-hard / NP-complete, not toy exercises:

Qubit routing / SWAP mapping — NP-complete Magic-state scheduling — NP-hard Tensor-network contraction ordering — NP-hard Pulse control / GRAPE — non-convex optimal control

Running Amp in a basic mode against Claude Code with Claude Fable 5 at max effort, Amp produced correct solutions faster and at a fraction of the cost. On the full run, Amp reached correctness 1.000 for a total of $4.59; Claude’s max-effort run cost dramatically more, and several of its tasks were cut short by monthly billing limits (see the deck for the careful, same-task breakdown).

The moment that named this project
“If a basic agent in rush mode solved it easily, maybe it wasn’t worth using Fable Max?” — Claude Fable 5, on being shown the results.

We replied: “Are you sure QMAP is a basic problem? Check again.” Fable reconsidered and conceded: qubit routing is NP-complete. The “basic” harness had quietly solved a hard problem — cheaper and faster than the “max-effort” one.

Experiment 02 · “how do I know the code is good?”

Can you prove it? Lean 4 + CBMC.

The benchmark showed which agent won. It did not, by itself, prove the generated code was correct. So we added machine-checked evidence — the strongest honest answer to “give me a proof.”

Lean 4 proves the task specifications and checker invariants are sound (unbounded), e.g. QMAP routing never lets two logical qubits collide and every physical gate decodes to a unique logical gate; magic-state scheduling respects the critical-path lower bound; tensor contraction needs exactly n−1 steps. CBMC then closes “gap A” on the real C++ checker: exhaustive bounded model checking finds no undefined behaviour and confirms the certifier is sound — 0 of 247 checks failed.

Honest scope: we certify the checker (so every accepted solution is provably valid), not the NP-hard solver; we don’t claim optimality; and CBMC is bounded (exhaustive up to a size). That’s the point — a small, twice-verified verifier you can actually trust.
