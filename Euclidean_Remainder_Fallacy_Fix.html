The Fix That Didn't Work

FAILED ❌

The explicit cast workaround — and why the optimizer still miscompiles it

// Attempted fix: make the conversion explicit
int test(int v) {
    int rem = v % 5;
    unsigned urem = (unsigned)rem;
    return 6U < urem ? 1111 : 2;
}
Result: Still prints 2 under /O1. The explicit cast doesn't help.
Why? Because the optimizer's range analysis is broken at the source — it assigns v % 5 the range [0, 4] (wrong), then tracks that wrong range through every variable and cast.
Root Cause
02

How the Optimizer Tracks the Wrong Range

The broken range analysis propagates through every intermediate variable

v % 5→ range [0, 4]  (WRONG — should be [-4, 4])
↓
rem→ range [0, 4]  (tracked through assignment)
↓
urem→ range [0, 4]  (tracked through cast — [0,4] as unsigned is still [0,4])
↓
6U < urem→ “always false” → constant-fold to 2 ❌
Key insight: No amount of intermediate variables or explicit casts fixes this. The optimizer propagates the wrong range through all of them. The cast from [0,4] to unsigned is still [0,4] — the damage was done before the cast.
Working Fix
03

The Fix That Works — volatile

WORKS ✅

volatile forces a memory read — the optimizer cannot track the range

#include <cstdio>

// Fix: volatile breaks the optimizer's range tracking
int test(int v) {
    volatile int rem = v % 5;
    return 6U < (unsigned)rem ? 1111 : 2;
}

int main() {
    int res = test(-1);
    printf("%d\n", res);  // prints 1111 under /O1 ✅
    return 0;
}
Result: prints 1111 under /O1. The volatile keyword forces the compiler to read rem from memory on every use, so it cannot propagate the (wrong) range [0,4] through to the comparison. The comparison must be evaluated at runtime.
How it works: volatile tells the compiler the value may change externally, so it disables all range tracking and constant folding through that variable. The comparison 6U < (unsigned)rem is preserved in the generated code.
Working Fix
04

The Fix That Works — #pragma optimize

WORKS ✅

Disable the optimization pass for the affected function only

#include <cstdio>

// Pragma MUST be outside the function — before and after
#pragma optimize("", off)
int test(int v) {
    return 6U < (v % 5) ? 1111 : 2;
}
#pragma optimize("", on)

int main() {
    int res = test(-1);
    printf("%d\n", res);  // prints 1111 under /O1 ✅
    return 0;
}
Result: prints 1111 under /O1. The #pragma optimize("", off) disables all optimizations for the next function definition. The comparison is preserved and evaluated correctly.
Important: The pragma must appear BEFORE the function — not inside it. Placing it after the function body has no effect. The matching #pragma optimize("", on) restores optimization for subsequent code.
volatileBreaks range tracking for one variable. Minimal performance impact. Most surgical.
