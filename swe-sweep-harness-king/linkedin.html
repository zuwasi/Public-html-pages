Full post

We ran two coding agents on Meta Superintelligence Labs' SWE-sweep benchmark. Same model in both. Only the harness differed. The model: Claude Opus 5.5, identical on both arms. The harnesses: Amp (default mode) vs Claude Code (headless). The task: 12 real open-source repos, 5 hidden reference bugs each, 60 scored tasks, one hour per session. C, C++, C#, F#, Java, Python, Rust. Result, scored by the official SWE-sweep Docker verifiers: Amp: 4/60 bugs resolved (6.7%) Claude Code: 2/60 (3.3%) For scale: the best official SWE-sweep leaderboard entry, GPT-5.6 Sol on mini-SWE-agent, resolves 4.7% of 4,100 bugs for $7,230 per run. Our Amp result lands above that on our subsample, for an estimated $28-48. What the agents actually fixed: a binary-mode config write in click, an overflow in tokio's size_hint (Claude), a null re-entry bug in RxJava's FlowableCreate. What they failed: a 399-line plausible-looking patch on z3 that scored exactly 0, and a roslyn fix that the regression gate zeroed because it broke one existing test. SWE-sweep scores the patch, not the intention. We also ran a control: Parasoft C++test, five configurations including MISRA C 2025 and MISRA C++ 2023, on six C/C++ repos. Half a million findings. Line-level overlap with the real bugs: 0-0.3%. These behavioral bugs need an agent that reads code, forms hypotheses and runs tests. Static analysis answers a different, equally important question: the rule book. SWE-sweep's own authors ran a harness ablation: Claude Code and Codex do not significantly outperform mini-swe-agent. Our data adds a production-harness data point: on identical weights, Amp resolved 2x the bugs, finished every session inside the cap, and won our earlier quantum-compiler kernel study too (4/4 vs 3/4 at 39x lower cost). The models are converging. The scaffolding is diverging. The model is the engine; the harness is the car.
