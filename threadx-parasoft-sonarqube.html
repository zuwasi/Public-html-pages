/* count is a live, volatile-derived input */ size = (UINT16)(count * 4u); p = (UCHAR *)malloc((size_t)size); if (p == TX_NULL) return HR_FAIL; memcpy(p, sa_src, (size_t)count * 4u); free(p);

Why this is a flow-analysis target

Allocation size is narrowed to 16 bits. The copy retains the full-width product.

Trigger source: volatile sensor count.

Runtime control: producer writes 0–15, so this path stays in-range in the demo.

Detection demand: track value range from source through two different expressions to the allocation/copy pair.

Related size cases also include negative-to-size_t, off-by-one indexing, pointer-sized memcpy, and stale length validation.

Ground-truth audit

Post-scan adjudication changed the denominator

Audit before scoring
Excluded candidate · BUG-005

The arithmetic cannot wrap on Win32

payload_len is UINT16. Its maximum plus 16 is 65,551, below 32-bit ULONG. Not a valid overflow on this target.

Excluded candidate · BUG-031

Guard makes the second result non-NULL

Both lookups use the same range guard. A non-NULL accessor result implies the primary lookup is also non-NULL.

Clean baseline contamination

One real unmarked over-read

sa_store_len can copy up to 65,535 bytes from sa_src[128]. This predates the planted diff and is tracked separately.

Scoring rule

Root-cause match required

Partial or indirect nearby diagnostics count as misses in strict recall. The 20-second soak is only a survival check, not proof of safety.
