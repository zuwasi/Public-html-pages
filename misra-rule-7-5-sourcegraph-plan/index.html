Mechanically findable, mechanically fixable

THE ENGINEERING LOOP · PARASOFT STARTS AND VERIFIES, SOURCEGRAPH ACTS

The loop: Parasoft measures, Sourcegraph fixes, Parasoft decides

Parasoft opens the loop and closes it: the baseline scan sizes the problem, and every later scan is the verdict on Sourcegraph's work. Zero is when the verifier says zero, not when the tool claims it. On any non-zero scan we go straight back to script design, exactly as shown by the red loop.

STEP 5 IN DETAIL · DESIGNING THE SCRIPTS, EXACTLY

Two mechanical transformations, value-preserving by construction

Value never changes. The numeric value is identical before and after; only the form moves. The compiler and CI protect anything the automation could get wrong, and every diff is human-reviewed before merge.
The automation knows what not to touch. A short expert-owned list is never auto-fixed, shown right.
Draft by default
The batch change ships as an unreviewed draft. Nothing merges until the team signs off and CI is green on every repo.
These scripts are versioned design artifacts, not one-shot runs: if the Parasoft verification scan still reports findings, the script is redesigned (v2, v3, ...) and the loop repeats until the verifier reports zero. That path is the red loop in the flowchart.
SAFETY RAILS

Four edge cases are routed to human experts, never to the automation

Signed minimum: INT32_MIN
INT32_C(-2147483648) cannot become (-INT32_C(2147483648)), because 2147483648 does not fit in a 32-bit signed type. The compliant form is ((-INT32_C(2147483647))-1). The automation excludes it; an expert fixes the handful of cases.
Range checks after suffix removal
The argument must fit the macro's type. Any value that was already out of range is surfaced early by the compiler and the scanner, which is the correct signal.
Non-literal arguments
INT32_C(OTHER_MACRO) or INT32_C(2+3) are also violations, but need a human decision. A dedicated query collects them into a short manual-review list.
Release-branch pinning
Branch-scoped queries with Sourcegraph revision syntax confirm zero on active release branches, so the fix set is proven everywhere it matters.

STAYING AT ZERO

Zero is proven twice, then held automatically

Proof 1 · Sourcegraph: the finder becomes the auditor
The exact queries from step 1 run again, and on release branches. Zero results means the pattern is gone at source level, confirmed in seconds, any time. The same query also runs as a CI guard on every pull request, so a new violation is blocked at the PR that introduced it.
Proof 2 · Parasoft: the scanner certifies it
A full Parasoft C/C++test scan of the whole project reports zero Rule 7.5 findings. That report is the compliance evidence of record for auditors and certification, and it reruns in the pipeline on every merged change.
Zero violations become a property of the process, not a one-time achievement: the guard query stops new violations at the pull request, and the scanner re-certifies the merged result continuously.
