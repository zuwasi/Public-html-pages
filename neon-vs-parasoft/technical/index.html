Method · 03

The Neon campaign: 14 autonomous hunts, scored against the oracle

One Amp thread per repository, the same scoring rule as the Parasoft arm: a finding counts only if it identifies the defect the maintainers actually fixed

SWE-sweep oracle per bug: pre-fix file blob + changed lines + the maintainer's fix commit
   |
   v
14 autonomous Amp threads, Gemini 4 Neon, one per repository
   |  open-ended multi-hour bug hunts: no bug hints, no hidden tests, no reward signal
   |  each thread delivers one consolidated report plus a findings JSON (2,288 findings total)
   v
per-bug verification: every candidate match judged against the fix diff
   |  accepted only when the finding names the same defect the maintainer's commit changed
   |  line overlap with a different mechanism counts as a miss
   v
result: 89 of 488 bugs matched on changed lines (18.2%), 73 on the exact line (15.0%)
      2,199 of 2,288 findings (96.1%) describe defects outside the benchmark's bug list
Scoring identical to the Parasoft arm: region = any changed line of the bug, strict = the exact line the fix removed or rewrote. Per-bug verdict write-ups with fix commits: reports/<repo>_scored.md in the benchmark repository

The claim · 08

Google's cleanest evidence: the harness is worth a multiple

The same model measured twice on SWE-sweep, once in a minimal shared harness and once in the vendor's agent: SWE-sweep subtask-weighted reward

The swing
3.0x

Neon's own mini-SWE to Antigravity delta. Google's blog calls it "more than triples": the announcement itself argues the harness, not just the model

The counterexample

Sol's Codex harness scores below mini-SWE (8.3 vs 11.6). Harness effects are not free wins: a badly matched agent loop can subtract. That is why the harness under the claim must be named

Comparison · 09

39.0% claimed, 18.2% measured: the fine print that lets both be true

Three differences separate the numbers: the harness, the task subset, and the scoring metric

Google's 39.0%
  • Harness: Antigravity-CLI 1.5.9, with default sub-agent fan-out across the codebase
  • Subset: full SWE-sweep, 4,068 bugs across every language
  • Metric: subtask-weighted reward, hidden tests in the loop, self-computed
Our 18.2%
  • Harness: Amp threads, open-ended hunt, no test feedback
  • Subset: the 14 C/C++ repos only, the benchmark's hard tail: all leaderboard bests together resolve 5.1% here
  • Metric: strictest possible: the finding must name the defect the maintainer's commit actually changed
What we could not run

Neon inside Antigravity-CLI on these 14 repos: no access. The model-versus-harness decomposition stays a labeled inference, not a measured A/B

The direction is consistent

On the full benchmark, mini-SWE to Antigravity triples Neon's score. Amp on a harder subset with a stricter yardstick lands between 12.8% and 39.0%. Nothing in our data contradicts the claim

What nobody should do

Never quote 39.0% as "the model finds 39% of real bugs": it is model plus fan-out harness plus reward weighting, and SWE-sweep's own leaderboard best resolves 9.5%

Our Neon runs were bug hunts, not SWE-sweep episodes: they did not attempt fixes or hidden tests, so our 18.2% measures discovery and identification only. 22 November 2026

Analysis · 11

Why Amp probably scored lower: what we measured vs what we infer

No Antigravity A/B exists on these repos, so the decomposition stays honest: measured patterns first, inferred causes second

Measured · exploration, not alignment

96.1% of Neon's 2,288 findings are novel, defects the benchmark never cataloged (our Claude Code calibration showed the same: 72 of 79 outside the bug list). Without a reward signal the model hunts its own path and does not prioritize the planted defects

Measured · localization is the bottleneck

SWE-sweep's authors showed line-range hints double or triple agent scores. Neon finds real defects but rarely lands on the oracle lines. Coverage splits the same way: C repos 31.0% region, C++ 13.8%

Measured · harness matters in our own data

On duckdb, Neon under Amp matched 18 of 109 (16.5%) versus the cold Claude Code calibration's 7 of 109 (6.4%): same kind of open hunt, different harness and effort, nearly 3x apart

Hypothesis · Amp-specific factors, probably affected, not proven
  • No hidden-test loop: nothing steers the hunt toward the oracle defects
  • One consolidated report per multi-hour thread instead of fresh per-task instances
  • Context compaction across multi-hour runs
  • Amp's default thinking settings rather than the model card's highest settings
The honest statement: we ran one configuration of one harness. Each knob above is a candidate explanation, testable by rerunning Neon in a fan-out harness with test feedback on the same 14 repos. 22 November 2026
Verdict · 12

Read every agentic number as model plus harness

The supplement's conclusion, and the experiment that would settle it

Read the claim:   Neon 39.0% on SWE-sweep  =  model + Antigravity-CLI 1.5.9
                    Google says so itself: 12.8% in mini-SWE, 39.0% in Antigravity

Read our number:  Neon 18.2% region / 15.0% strict  =  model + Amp,
                    hardest subset (leaderboard bests: 5.1%), strictest scoring,
                    discovery only, no fixes, no hidden tests

The harness share: the mini-SWE to Antigravity delta (up to 3x) is larger than
                    any model-to-model gap in the agentic coding rows of the card.
                    The harness is not overhead around the model; it is part of the claim

The model itself: strong where the search space is small. Neon beats Parasoft's
                    exact-line rate on libexpat, arrow and micropython; 96.1% of its
                    findings are genuine defects outside the benchmark list

The untested experiment: Neon with fan-out sub-agents and hidden-test reward
                    on our 14 repos. That number, not 39.0% or 18.2%, settles
                    the model-versus-harness question
For safety-critical buyers, the parent deck's verdict stands unchanged: a vendor-harness benchmark number is a marketing configuration until reproduced in your toolchain and your harness
