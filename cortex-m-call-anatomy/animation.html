What really happens when C calls a function? Watch the CPU do it.

The animations below are not drawings. add.c is compiled with arm-none-eabi-gcc 14.2 for Cortex-M4, the machine code runs in the Unicorn CPU emulator, and every register, stack word and PC value is read back from the emulator after each instruction. Yellow = instruction just executed, blue = PC, red = state changed, grey stack rows = dead frames.
Static infographic: -O0 vs -O2 vs forced call Source code and the Python visualizer (MIT)

Three builds in lockstep: -O0, -O2, and -O2 with a call the optimizer cannot remove

Same C, same CPU, only the -O flag changes. The -O2 build is done after 2 instructions (movs r0, #0; bx lr) while -O0 is still setting up its stack frame. -O0 finishes after 30 instructions, the forced call after 13.

-O0 in detail: the textbook call, spills and all

Arguments land in R0 and R1, bl add writes the return address into LR, add spills both arguments to its stack frame and reloads them, the sum comes back in R0, and bx lr returns. Watch the dead frame of add (greyed rows below SP) still holding 10 and 20 after the return.

Reproduce it

git clone https://github.com/zuwasi/cortex-m-call-anatomy, pip install -r requirements.txt, then python callviz.py --compare O0 O2 forced. Space plays and pauses, the arrow keys step one instruction at a time.

Toolchain: Arm GNU Toolchain 14.2.Rel1, -mcpu=cortex-m4 -mthumb. Emulator: Unicorn 2.1.4 (ARMv7-M, Thumb).
